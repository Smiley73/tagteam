# Lens: user experience

What will this feel like to the person using it?

Look for: an action with no feedback; a destructive action with no confirmation
or no undo; an error message that names an internal cause rather than what to do
next; a loading state absent, so the screen looks broken; an empty state that
shows nothing rather than explaining what would be there; a flow that loses the
user's work on a mistake; a control whose label does not say what it will do.

Judge against the interface decisions recorded in `goal.md`. Those were settled
by a person and are not yours to reopen — you are checking whether the code
implements them, not whether they were right.

Not yours: visual polish, wording preferences, accessibility (a separate lens).
